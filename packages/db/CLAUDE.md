# @smm/db

Drizzle ORM schemas, client, RLS helpers, and migrations for the project's single Neon Postgres database.

## Layout

- `src/schema/` — one file per logical table or table group, all re-exported from `src/schema/index.ts`.
- `src/client.ts` — Neon serverless driver + Drizzle wrapper.
- `src/rls.ts` — `workspaceFilter()`, plus re-exports of `eq`/`and`/`isNull` for callers.
- `migrations/` — generated SQL files (committed) + `meta/` snapshots (also committed).
- `drizzle.config.ts` — points at `./src/schema/index.ts` and reads `DATABASE_URL`.

## Generating migrations

```bash
cd packages/db
DATABASE_URL=postgresql://placeholder@localhost/placeholder pnpm exec drizzle-kit generate
```

Drizzle reads the current schema files, diffs against the latest snapshot in `migrations/meta/`, and emits a new `NNNN_<name>.sql`. A placeholder `DATABASE_URL` is fine for `generate`; only `migrate` actually connects.

## Critical schema patterns

- **`chunks.tsv`** is a `tsvector` column declared with `customType` since Drizzle has no built-in tsvector. Always compute it at insert time via `sql\`to_tsvector('english', ${content})\`` — never pass a string.
- **`chunks.embedding`** is `vector(1024)` for `voyage-3` output. Insert as `sql\`${'[' + arr.join(',') + ']'}::vector\``.
- **HNSW + GIN indexes** for chunks live in `migrations/0001_chunk_indexes.sql` (manual file, not auto-generated by drizzle-kit).
- **pgvector extension** is enabled by the first migration (`0000_enable_pgvector.sql`, manual).

## Tenant scoping

`SET LOCAL` session vars do not survive PgBouncer transaction-mode pooling. Tenant scoping is enforced in application code via `workspaceFilter()` — never via Postgres RLS. See `.claude/rules/workspace-scoping.md`.

## Conventions

- Tables that belong to a workspace carry `workspaceId uuid NOT NULL`; tables that can be shared across workspaces (e.g. shared-niche `chunks`) make it nullable and treat `NULL` as "shared".
- Tables that belong to a client carry `clientId uuid NOT NULL` plus the `workspaceId` for fast filter chains.
- Soft delete uses `deletedAt timestamp with time zone` (nullable). Callers add `isNull(table.deletedAt)`.
- Each table exports `<TableName>` (`$inferSelect`) and `New<TableName>` (`$inferInsert`) types.
